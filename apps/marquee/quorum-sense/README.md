# Quorum Mobile

Quorum is the first Marquee mobile candidate.

## Mobile Job

Help an organization capture live signal, preserve ambiguity, and move toward
quorum while people are away from a desktop.

## Expected Native Work

iOS:

- SwiftUI participant and facilitator flows
- Foundation Models for local summarization, extraction, and structured signal
  drafts
- Speech for live transcription
- Vision and AVFoundation for photo/camera signal capture
- App Intents for quick capture

Android:

- Compose participant and facilitator flows
- Gemini Nano and ML Kit GenAI APIs for local summaries and extraction
- CameraX for capture
- ML Kit for OCR and document/signal extraction
- MediaPipe where realtime visual signals become product-critical

Rust:

- Inquiry thread state
- Signal and hypothesis DTOs
- fuzzy confidence handling
- offline event queue
- replay and deterministic checks
- vector memory contracts
- AI routing policy

## Rust / UniFFI Bindings

The product FFI crate is `apps/marquee/quorum-sense/ffi`. The canonical contract lives in
`schemas/quorum-mobile.udl`; `apps/marquee/quorum-sense/ffi/src/quorum_mobile.udl` is a
byte-identical compiled copy checked by `scripts/check-mobile-scaffold.sh`.

Regenerate native bindings from the repo root (requires Xcode on macOS for iOS,
JDK 17 + Android SDK/NDK + `cargo-ndk` for Android):

```sh
bash scripts/build-mobile-ffi-ios.sh      # XCFramework + Swift bindings -> ios/CoreBridge/
bash scripts/build-mobile-ffi-android.sh  # jniLibs + Kotlin bindings -> android/app/src/main/{jniLibs,java/uniffi}/
```

Generated artifacts are gitignored and regenerated by the scripts. Production
shells use `QuorumCoreBridgeFFI`; previews/tests keep `PreviewQuorumCoreBridge`.

## AI Director (local Quorum)

DEBUG builds call `quorum_configure_director_api` at startup with:

- `QUORUM_BASE_URL` (default `http://127.0.0.1:5161/quorum-sense`)
- `QUORUM_BEARER_TOKEN` (default `dev` when Quorum runs with `LOCAL_DEV=true`)

`quorum_current_director_snapshot()` tries `GET {base}/api/director/snapshot`
and falls back to the committed fixture until Plan 2 exposes the server route.
Intent submit (`quorum_submit_director_intent`) is stored locally only — session
push waits on Plan 2.

## First Workflow To Specify

Capture a field signal from text, voice, or photo, create a local structured
draft, let the user consent, then append it to a Quorum inquiry thread when
online.
