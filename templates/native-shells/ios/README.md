# iOS Native Shell Template

A minimal, buildable SwiftUI app that proves the iOS build + simulator + Rust-via-UniFFI pipeline. **Not a product app** — it lives here so any of the marquee/studio mobile apps can copy this structure and inherit a working build.

## What's here

```text
ios/
  project.yml                  # XcodeGen spec — generates ReflectiveShell.xcodeproj
  App/
    ReflectiveShellApp.swift   # @main SwiftUI entry point
    ContentView.swift          # Hello screen — calls greet() from Rust
  CoreBridge/                  # XCFramework + Swift binding (regenerated)
  .gitignore                   # Excludes generated artifacts
  README.md                    # This file
```

The `.xcodeproj`, the `CoreBridge/ReflectiveShellFFI.xcframework`, and `CoreBridge/ReflectiveShellFFI.swift` are **not committed** — they're regenerated by `just ios-uniffi` and XcodeGen.

The Rust side lives at `crates/shell-ffi/` (product-neutral; just `greet()` and `coreVersion()` to prove the round-trip).

## Prerequisites

- Xcode 15+ installed at `/Applications/Xcode.app` (Command Line Tools alone are not enough)
- `xcode-select -p` points to the full Xcode (`sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`)
- XcodeGen: `brew install xcodegen`
- `just`: `brew install just`
- Rust toolchain (already required by the workspace). iOS rustup targets (`aarch64-apple-ios`, `aarch64-apple-ios-sim`, `x86_64-apple-ios`) are auto-installed by `scripts/build-shell-ffi-ios.sh` the first time.

## Build and run

From the repo root:

```sh
just ios-uniffi             # build Rust → XCFramework + Swift binding
just ios-build              # ios-uniffi + xcodegen + xcodebuild for iPhone 16 sim
just ios-sim                # ios-build + boot simulator + install + launch
just ios-sim "iPhone 15 Pro"  # override device
```

`ios-build` and `ios-sim` chain through `ios-uniffi` automatically, so a fresh run is one command. To skip the Rust rebuild (e.g. when only Swift changed), invoke `xcodebuild` directly.

## Adoption path

To start a real iOS app (post-v1, post-trigger):

1. Copy this directory to your product app, e.g. `apps/marquee/<app>/ios/`.
2. Rename `ReflectiveShell` → your product name in `project.yml` and Swift sources.
3. Adopt the contract structure as the app grows:

   ```text
   App/         — SwiftUI navigation and lifecycle
   Capture/     — AVFoundation, PhotosUI, Vision, Speech
   PlatformAI/  — Foundation Models, Core ML
   CoreBridge/  — UniFFI-generated bindings + thin Swift adapters
   Resources/
   Tests/       — platform tests + fixture parity vs Rust
   ```

4. Wire UniFFI bindings from your shared Rust crate into `CoreBridge/`.

Do not put product invariants in Swift unless they are platform-specific.

## Verification status

**Verified by Claude on host:**
- `crates/shell-ffi` compiles, `cargo test -p reflective-shell-ffi` passes
- `uniffi-bindgen` generates valid Swift bindings from the host dylib (Swift API: `greet(name:)`, `coreVersion()`)

**Not verified by Claude** — the dev machine has Command Line Tools only, no Xcode.app:
- iOS rustup target cross-compile (aarch64-apple-ios, *-sim, x86_64-apple-ios)
- `xcodebuild -create-xcframework` assembly
- XcodeGen `project.yml` schema (current as of XcodeGen 2.x)
- `xcodebuild` for-simulator build
- `xcrun simctl install` + `launch` flow

First run on a machine with Xcode installed should be treated as the actual verification step. Expected failure modes: XcodeGen schema drift, simulator device name mismatch (use `xcrun simctl list devices available` to confirm), Xcode license not accepted (`sudo xcodebuild -license accept`), missing rustup iOS targets (the script auto-installs them), modulemap not auto-discovered inside the XCFramework Headers/ (it's renamed to `module.modulemap` by the script — clang convention).
